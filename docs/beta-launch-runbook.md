# TaxiVillage — запуск beta в Ушарале

## Перед деплоем

1. Сделать snapshot/backup production PostgreSQL в Render.
2. Проверить, что persistent disk `taxivillage-uploads` подключён к backend.
3. Развернуть текущий commit в staging и выполнить `npx prisma migrate deploy`.
4. Пройти один заказ каждой ролью на staging.
5. Только после этого развернуть тот же commit в production.

Миграция сохраняет старые food-заказы, оставляет старые способы оплаты для такси и
автоматически помечает уже существующие заведения как проверенные. Новые заведения
создаются со статусом `PENDING`.

## Настройка beta

1. В админке создать 3–5 заведений.
2. Для каждого заполнить адрес, контакт, доставку 700 ₸, радиус, график и меню.
3. Проверить заведение кнопкой `Проверить`.
4. Одобрить 5–8 водителей. Подходит водитель с активной возможностью Taxi или Courier.
5. Промокод `USHARAL500` создаётся миграцией:
   - скидка 500 ₸;
   - минимальный чек 1 500 ₸;
   - максимум 100 использований;
   - один раз на пассажира.
6. До регистрации ИП оставить первые 30 заказов каждого партнёра бесплатными.

## Контрольный заказ

1. Пассажир выбирает заведение и блюда.
2. Указывает адрес вручную или выбирает геопозицию.
3. Выбирает наличные или Kaspi и создаёт заказ.
4. Заведение проходит этапы `Принят → Готовится → Искать водителя`.
5. Водитель открывает `Доставка еды`, принимает предложение и проходит этапы
   `В заведении → Заказ забран → Доставлен`.
6. Пассажир видит водителя, цены и статусы.
7. В админке заказ появляется в экономике только после `DELIVERED`.

## Реакция на проблемы

- `PLACED` дольше 5 минут: заказ появляется в `Проблемах`, администратору с push
  token отправляется уведомление.
- `SEARCHING_DRIVER` дольше 10 минут: назначить водителя вручную.
- Недоступное блюдо: заведение отменяет заказ с причиной.
- Двойное принятие: backend закрепляет заказ только за первым водителем.
- Долг заведения 10 000 ₸ или больше: новые заказы временно блокируются до
  регистрации оплаты в админке.

## Ежедневные метрики

- создано и доставлено заказов;
- отмены и причины;
- медиана времени принятия;
- медиана поиска водителя;
- GMV, скидки, комиссия и долг партнёров;
- количество повторных покупателей;
- количество ручных назначений.

## Откат

- Не откатывать production-БД удалением новой миграции.
- При проблеме остановить новые заказы, установив партнёрам `SUSPENDED`.
- Вернуть предыдущую backend/mobile версию, сохранив новые nullable-колонки.
- Восстанавливать БД из snapshot только при подтверждённой порче данных.
